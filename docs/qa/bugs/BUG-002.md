# BUG-002 — Lịch đã hoàn thành vẫn lùi trạng thái qua PATCH

| Trường | Giá trị |
| --- | --- |
| Module | Lịch hẹn |
| Severity / Priority | High / P1 |
| Trạng thái | Open |
| Phát hiện và tái hiện | 13/11/2026, Windows, Node.js 22.15.0, MongoDB QA local |
| Requirement / case | REQ-APPT-006 / TC-APPT-021 |
| Nguồn | Working tree dựa trên 68a2e6a; hash nguồn trong evidence |

## Tiền điều kiện và bước tái hiện

1. Đăng nhập Admin trên DB QA.
2. Chuẩn bị một lịch hẹn riêng ở trạng thái `Đã hoàn thành`.
3. Gửi `PATCH /api/appointments/:id` với body `{"status":"Đang điều trị"}`.
4. Gọi `GET /api/appointments/:id` để kiểm tra dữ liệu đã lưu.

**Expected:** HTTP 400; trạng thái vẫn `Đã hoàn thành` theo quy tắc không lùi trạng thái trong test plan.

**Actual:** HTTP 200; GET trả trạng thái `Đang điều trị`. Lỗi làm hồ sơ điều trị đã hoàn tất có thể quay lại trạng thái đang xử lý.

## Bằng chứng và nguyên nhân nghi vấn

[TAP thực thi](../evidence/2026-11-13/known-defects-results.tap), test `BUG-002 / TC-APPT-021`; assertion chứa cả status HTTP và trạng thái đọc lại. [Hash nguồn](../evidence/2026-11-13/source-hashes.json).

Tái hiện lại trong [run có build/Run ID](../runs/QA-20261113T073749688Z-18594c/execution.json): vẫn Fail, HTTP 200 và trạng thái bị lùi. Lịch sử trạng thái ở [registry](registry.json).

`server/server.js` gắn `app.patch('/api/appointments/:id', protect, appointmentController.finishTreatment)` trước router có kiểm tra `STATE_ORDER`. Handler `finishTreatment` gán thẳng trạng thái từ body, nên lớp kiểm tra trong router không được gọi. Đây là phân tích từ mã nguồn; chưa có bản sửa được xác nhận.
