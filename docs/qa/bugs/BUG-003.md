# BUG-003 — Hoàn thành lịch hẹn lặp tạo hai hóa đơn

| Trường | Giá trị |
| --- | --- |
| Module | Lịch hẹn / Hóa đơn |
| Severity / Priority | High / P0 |
| Trạng thái | Open |
| Phát hiện và tái hiện | 13/11/2026, Windows, Node.js 22.15.0, MongoDB QA local |
| Requirement / case | REQ-PAY-009 / TC-APPT-022 |
| Nguồn | Working tree dựa trên 68a2e6a; hash nguồn trong evidence |

## Tiền điều kiện và bước tái hiện

1. Đăng nhập Admin trên DB QA.
2. Chuẩn bị lịch riêng ở trạng thái `Đang điều trị`, dịch vụ giá 100.000 VND.
3. Gửi `PATCH /api/appointments/:id` với `{"status":"Đã hoàn thành"}`; xác nhận HTTP 200.
4. Gửi lại đúng request hoàn thành cho cùng lịch.
5. Gọi `GET /api/invoices?appointmentId=:id`.

**Expected:** Chỉ một hóa đơn gắn lịch; request lặp bị từ chối hoặc xử lý không tạo side effect trùng.

**Actual:** Danh sách trả **hai hóa đơn** cho cùng appointment. Có nguy cơ thu tiền trùng hoặc đếm doanh thu hai lần; chưa kiểm thử tác động thực tế trên dashboard hay quy trình thu tiền.

## Bằng chứng và nguyên nhân nghi vấn

[TAP thực thi](../evidence/2026-11-13/known-defects-results.tap), test `BUG-003 / TC-APPT-022`: expected invoice count 1, actual 2.

`finishTreatment` gọi `Invoice.create()` mỗi lần nhận trạng thái hoàn thành; không kiểm tra hóa đơn tồn tại. Model Invoice chưa có unique constraint trên `appointmentId`. Cần xử lý cả request lặp và cạnh tranh đồng thời; lần tái hiện này mới gửi tuần tự.

## Tái chạy và tiêu chí đóng

```sh
node --env-file=testing/.env.test --test --test-name-pattern=BUG-003 testing/api/known-defects.test.js
```

Chỉ đóng khi request hoàn thành lặp không tạo hóa đơn thứ hai và regression luồng hoàn thành lần đầu vẫn Pass. Cần bổ sung xác minh concurrent requests trong chu kỳ sửa lỗi; chưa có kết quả cho trường hợp đó.
